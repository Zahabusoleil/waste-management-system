PROMPT 01: MASTER DEVELOPMENT INSTRUCTION

Act as a Senior Full-Stack Software Engineer, MongoDB Database Architect, Application Security Engineer, UI/UX Designer and Software Quality Assurance Engineer.

Your responsibility is to develop a complete, professional, functional and secure web application named:

ECOTRACK — WASTE MANAGEMENT AND COLLECTION TRACKING SYSTEM.

PROJECT OBJECTIVE:

Develop a web-based application that allows residents to report waste problems, administrators to manage reports and assign collection tasks, and waste collectors to manage assigned collection activities.

TECHNOLOGY STACK:

Frontend:

- HTML5
- CSS3
- Vanilla JavaScript

Backend:

- Node.js
- Express.js

Database:

- MongoDB Atlas
- Mongoose

Security:

- bcrypt password hashing
- Secure authentication
- Role-Based Access Control (RBAC)
- Input validation
- Secure session/token management

USER ROLES:

1. RESIDENT

- Register an account.
- Log in and log out.
- Submit waste reports.
- View personal reports.
- Track report status.
- Edit or delete eligible personal reports.

2. ADMINISTRATOR

- Access a protected administrator dashboard.
- View and manage users.
- View and manage waste reports.
- Create collector accounts.
- Assign collection tasks.
- Manage collection records.
- View system statistics.

3. WASTE COLLECTOR

- Log in using an administrator-created account.
- View assigned tasks.
- View collection locations.
- Update collection progress.
- Mark collection tasks as completed.
- View collection history.

STRICT DEVELOPMENT RULES:

- MongoDB must be the primary persistent database.
- Never replace MongoDB with localStorage or hardcoded arrays.
- Implement real backend APIs.
- Implement complete CRUD functionality.
- Separate models, routes, controllers and middleware.
- Use environment variables for secrets.
- Never expose database credentials.
- Never store plaintext passwords.
- Never allow public administrator registration.
- Never trust frontend authorization alone.
- Never create buttons that do nothing.
- Never create fake statistics or testimonials.
- Avoid unnecessary dependencies.
- Use clean and maintainable code.
- Do not overwrite useful existing files without permission.

SECURITY REQUIREMENTS:

Protect against:

- Unauthorized access.
- Privilege escalation.
- NoSQL injection.
- Cross-site scripting.
- CSRF where applicable.
- Brute-force login attempts.
- Malicious file uploads.
- Insecure direct object references.
- Mass assignment vulnerabilities.
- Sensitive information exposure.

Implement:

- Server-side RBAC.
- Password hashing.
- Authentication middleware.
- Authorization middleware.
- Rate limiting.
- Helmet security headers.
- Input validation and sanitization.
- Secure cookies or appropriately protected tokens.
- Proper CORS configuration.
- Safe error handling.
- Audit logs for important administrative actions.

DEVELOPMENT APPROACH:

Work in stages.

Before development:

1. Inspect the existing workspace.
2. Identify existing files.
3. Preserve useful code.
4. Plan the architecture.
5. Identify missing requirements.

After each stage:

1. Run relevant tests.
2. Identify errors.
3. Fix problems.
4. Explain completed work.
5. Report remaining limitations.
6. Never claim untested functionality works.

Do not deploy or expose the application publicly without explicit approval.

The final application must be professional, secure, responsive, accessible, maintainable and suitable for an academic software engineering final project.

Act as a Senior Application Security Engineer.

Implement secure authentication and Role-Based Access Control for EcoTrack.

This is a HIGH PRIORITY requirement.

A. RESIDENT REGISTRATION

Allow registration using:

- Full name
- Email
- Phone number
- Location
- Password
- Confirm password

Validate information on the backend.

Hash passwords using bcrypt.

Prevent duplicate email registrations.

Public registration must always assign the resident role.

Never accept administrator or collector roles from public registration requests.

B. LOGIN AND LOGOUT

Implement secure login and logout.

Use secure HttpOnly cookies with appropriate Secure and SameSite settings in production, or another carefully designed authentication strategy.

Do not store authentication tokens in localStorage.

Implement login rate limiting.

Use safe authentication error messages.

C. ROLE-BASED ACCESS CONTROL

RESIDENT:

- Access personal reports only.
- Submit waste reports.
- Edit or delete eligible personal reports.
- Never access administrator routes.
- Never access other residents' private information.

ADMINISTRATOR:

- Manage users.
- Manage waste reports.
- Create collector accounts.
- Assign collection tasks.
- Manage collection records.
- Access authorized statistics.

COLLECTOR:

- View assigned tasks only.
- Update assigned task status.
- View own collection history.
- Never create administrator accounts.
- Never access other collectors' tasks.

D. ADDITIONAL SECURITY

Implement:

- Server-side authentication.
- Server-side authorization.
- Object ownership checks.
- NoSQL injection protection.
- XSS protection.
- CSRF protection where applicable.
- Input validation and sanitization.
- Helmet.
- Rate limiting.
- Appropriate CORS.
- Secure error handling.
- Secure password management.
- Audit logs.

Never expose passwords, password hashes, database URIs or authentication secrets in API responses.

E. SECURITY TESTING

Test:

- Resident accessing administrator routes.
- Resident accessing another resident's reports.
- Collector accessing another collector's tasks.
- Unauthenticated access to protected APIs.
- Attempted administrator privilege escalation.
- Invalid input.
- Repeated failed login attempts.

Fix identified vulnerabilities and provide a security testing report.
